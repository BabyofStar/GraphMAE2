## 5. 方法定义与对照

所有组每轮均无放回选取恰好`K=floor(mask_rate*N)`个输入掩码节点，保持原训练预算与模型配置。

| 编号 | input_mask_mode | 机制与状态 |
| --- | --- | --- |
| B0 | `random` | 原始均匀随机基线 |
| B1 | `structure_static` | 对数度数引导，alpha始终为0.5；正式120次对照 |
| B2＝v1 | `structure_curriculum` | 对数度数引导＋课程调度；v2参照 |
| B3 | `structure_curriculum_shuffled` | 固定打乱评分与节点对应关系，沿用B2调度；正式120次对照 |
| D | `reconstruction_curriculum` | 历史逐节点重构误差EMA＋课程；完整开发9次 |
| S | `density_stratified` | 真实局部特征密度4层配额＋层内均匀随机；完整开发9次，无难度课程 |
| DS | `reconstruction_density_curriculum` | 密度配额内叠加D课程；已实现及工程测试，无完整训练结果 |
| R | `random_group_stratified` | 固定随机分组，组大小和配额与S相同；完整开发9次，独立产物审计待完成 |

### 5.1 v1：结构评分与课程

以去自环后的入度作为结构代理，采用对数变换：

```text
q_i = (log(1 + degree_i) + 1e-8) / sum_j(log(1 + degree_j) + 1e-8)
w_i(t) = (1 - alpha(t)) / N + alpha(t) * q_i

progress = epoch / max(total_epochs - 1, 1)
alpha(t) = 0.5 * clip((progress - 0.2) / (0.8 - 0.2), 0, 1)
```

前20%均匀随机，中间60%线性增加引导，最后20%固定0.5。alpha是引导强度，不是总掩码率；无放回采样权重不等于精确边缘入选概率。度数是结构代理，不能直接称为真实重构难度。课程进度独立传递，不改变原forward的epoch/EMA语义。

B3使用私有CPU生成器一次置乱评分，固定`structure_shuffle_seed=20261025`，各训练种子共用这次置乱，不额外消耗训练全局随机流。B1/B2的平均引导强度不同，不能仅据两者差异证明调度顺序的独立因果作用。

### 5.2 D：历史重构误差课程

从已发生的被掩码节点重构中取得逐节点SCE误差，detach/no_grad后更新EMA；首次观察直接赋值，后续beta=0.9。未观察节点用已观察误差的中位数填充，按0.95分位截断上端，保持正数下限后与均匀项混合，沿用0.5/0.2/0.8课程。

统计只影响未来采样，不增加额外前向、不替换训练损失、不改变教师EMA。重构困难不等于对分类更有价值，须由下游结果检验。

### 5.3 S：局部特征密度分层

以原始特征与唯一一、二跳邻居的平均余弦相似度定义密度；邻域按无向处理，去自环和重复，孤立节点密度为0。同分按节点ID稳定排序，近等量划分为4层，以最大余数法分配固定掩码配额，层内均匀无放回采样。

分块大小为256，不构造完整N×N相似度矩阵；当前实现仅验收三个小图。S从首轮起使用配额，不带D式难度课程。固定配额约束的是联合抽样数量，不能直接等同于更多可见邻居、类别均衡或更均匀的单节点累计次数。

### 5.4 R：固定随机分组配额对照

R用于检查S的收益是否依赖真实密度信息，而非只由一般分组配额或随机路径变化产生。

- 每图用私有CPU `torch.Generator`一次生成节点排列，按S的实际4组大小切分；组内采样沿用S的API、调用数量、张量形状和配额规则。
- Cora/Citeseer/PubMed的分组种子分别固定为**2026110301 / 2026110302 / 2026110303**，同一图在训练种子0/1/2下使用相同分组。
- 分组准备不改变训练全局CPU/CUDA随机状态，不使用标签、不根据成绩寻找有利分组。
- 真实`density_layer`和`local_feature_density`保留；随机组另记`sampling_group`、组内节点顺序、种子和指纹，避免诊断含义混淆。
- 训练期随机API形式相同不表示消除了所有随机性；节点集合和训练轨迹仍可不同。一份固定随机分组不能代表所有分组。

- S的均值高于本次固定随机分组R，为密度信息有用提供支持性线索；但R本身相对B2的等权差值为−0.5556，S−R的+0.6222不能当作S相对v1的改进幅度。
- PubMed种子0中R比S高0.2个百分点，不能说S每个种子都获胜。留一检查仍为正也不足以从n=3和单一分组宣布稳定、显著或确定的因果机制。
- 保留全部数据集与负结果，不挑最好种子，不把本表与正式测试表或论文测试成绩混合比较。

### 6.4 机制诊断与资源

原36次已审计的诊断显示：S确实固定了密度层配额，但累计单节点采样次数与B0几乎同样均匀。Cora的零可见二跳邻居比例略升而验证改善，Citeseer该比例下降而验证退步，因此“更多可见邻居解释S收益”的简单说法未获支持。Citeseer的48个非自环度0节点也未显示被S明显过采样，不能直接把退步归因于孤立点。

D评分确实改变采样，但其反馈误差与采样次数的相关性不是独立因果证据。R的完整节点反馈、资源和分组指纹将在新产物审计中继续复核。

原v2的B0/S平均预训练秒数分别为：Cora 130.68/132.32，Citeseer 54.83/54.72，PubMed 255.04/257.72。时间包含原中途探测和诊断，混有调度及I/O影响，不是严格隔离的算法开销。

v1的120次runner耗时合计约5.304小时，v2原36次约1.639小时，不包含全部外围调度和独立CPU重载开销。PyTorch allocated/reserved不是整卡显存，不能用设备型号或这些峰值替代实际配额。R的完整资源统计待审计后报告。
